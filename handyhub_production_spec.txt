# 📋 Handy Hub - Production-Ready Specification & Blueprint Document

## 🎯 APP GOALS & USER WORKFLOWS

### Primary Application Goals
Handy Hub is a service marketplace application designed to:
1. **Connect customers** with local service providers for home services (cleaning, plumbing, electrical, gardening, etc.)
2. **Enable service providers** to showcase their services, manage bookings, and grow their business
3. **Facilitate seamless booking and payment** processes between customers and providers
4. **Build trust** through verification systems, reviews, and ratings
5. **Provide administrative tools** for platform management and quality control

### Core User Journeys

#### Customer Journey
1. **Onboarding & Authentication**
   - Download app and complete registration (email/password)
   - Email verification required
   - Automatic profile creation via Supabase trigger

2. **Service Discovery**
   - Browse popular service categories on home screen
   - Search for specific services using search bar
   - View featured providers with ratings and reviews
   - Use AI assistant for service recommendations (planned feature)

3. **Booking Process**
   - Select service category → Choose specific service → Select provider
   - View provider profile, ratings, and service details
   - Select date/time for service
   - Confirm booking details and pricing
   - Receive booking confirmation

4. **Service Experience**
   - Track booking status (pending, confirmed, in-progress, completed)
   - Communicate with provider via in-app messaging (planned)
   - Rate and review service after completion
   - View booking history

5. **Account Management**
   - Update profile information
   - Manage payment methods (planned)
   - View earnings/spending history
   - Adjust notification preferences

#### Provider Journey
1. **Onboarding & Verification**
   - Register as provider (selecting "provider" user type during signup)
   - Complete provider profile with business details
   - Submit verification documents (license, insurance, etc.)
   - Await admin approval (verification_status: pending → verified)

2. **Service Management**
   - Add/edit/delete services offered
   - Set pricing, duration, and service areas
   - Update availability status
   - Manage emergency service offerings

3. **Booking Management**
   - View incoming service requests
   - Accept or decline booking requests
   - Update booking status (confirmed → in-progress → completed)
   - Communicate with customer (planned)
   - Track earnings and job history

4. **Profile & Reputation**
   - Maintain accurate business information
   - Respond to customer reviews
   - Track rating and review metrics
   - Update certifications and credentials

#### Admin Journey
1. **Platform Oversight**
   - Monitor user registrations and provider applications
   - Review and approve/deny provider verifications
   - Manage service categories and platform settings
   - Handle disputes and customer support issues
   - Analyze platform metrics and growth

2. **Content Moderation**
   - Review flagged content or inappropriate behavior
   - Manage service quality standards
   - Ensure compliance with local regulations

## 📖 TECHNICAL ARCHITECTURE DOCUMENTATION

### System Overview
Handy Hub is a cross-platform mobile application built with:
- **Frontend**: React Native with Expo framework
- **Backend**: Supabase (PostgreSQL database + Auth + Storage + Edge Functions)
- **State Management**: React Context and local component state
- **Routing**: Expo Router (file-based routing)
- **UI Components**: Custom components with Ionicons and LinearGradient

### API Endpoints (Supabase-Based)
The application interacts with Supabase through the JavaScript client:

#### Authentication
- `supabase.auth.signInWithPassword({email, password})`
- `supabase.auth.signUp({email, password, options: {data: {user_type, full_name}}})`
- `supabase.auth.getUser()`
- `supabase.auth.signOut()`

#### Profile Management
- `supabase.from('profiles').select('*').eq('id', userId).single()`
- `supabase.from('profiles').update(updates).eq('id', userId).single()`
- `supabase.from('providers').select('*').eq('id', userId).single()`

#### Service Discovery
- `supabase.from('service_categories').select('*').order('name')`
- `supabase.from('providers').select(...).order('rating', {ascending: false}).limit(5)`

#### Booking Management
- `supabase.from('bookings').select(...).eq('user_id', currentUser?.id).order('booking_time', {ascending: false}).limit(5)`

#### Provider Service Management
- Local state management (not yet connected to backend in provider/services.tsx)

### Data Flow
1. **Authentication Flow**
   - User enters credentials → Login component validates input → Calls Supabase Auth → On successful login, fetches user profile → Routes based on user_type

2. **Data Fetching Flow** (Example: Home screen)
   - Component mounts → useEffect triggers fetchData() → Gets current user from Supabase Auth → Fetches user profile via profileHelper → Fetches service categories → Fetches featured providers → Fetches recent bookings → Updates component state → Renders UI

3. **Data Mutation Flow** (Example: Adding service)
   - User fills form → Calls handleAddService() → Validates input → Creates service object → Updates local state → Shows success alert

## 🛑 PRODUCTION GAPS & VULNERABILITIES

### Security Vulnerabilities (OWASP Top 10)

#### A01:2021 - Broken Access Control
- **Gap**: No role-based access control on API endpoints
- **Risk**: Users could potentially access/modify other users' data
- **Evidence**: Direct Supabase queries without row-level security checks in many places

#### A02:2021 - Cryptographic Failures
- **Gap**: Environment variables exposed in code (`your-supabase-url`, `your-supabase-anon-key`)
- **Risk**: Hardcoded credentials, lack of proper secret management
- **Evidence**: `app/utils/supabase.ts` shows placeholder values

#### A03:2021 - Injection
- **Gap**: No visible input sanitization beyond basic validation
- **Risk**: Potential SQL injection through Supabase queries
- **Evidence**: String inputs used directly in queries without parameterization checks

#### A04:2021 - Insecure Design
- **Gap**: Missing security controls in provider verification flow
- **Risk**: Unverified providers could offer services
- **Evidence**: Verification relies on client-side checks only

#### A05:2021 - Security Misconfiguration
- **Gap**: No evidence of security headers, CORS policies, or rate limiting configuration
- **Risk**: Excessive data exposure, potential DoS attacks
- **Evidence**: Supabase configuration not visible for security settings

#### A06:2021 - Vulnerable and Outdated Components
- **Gap**: No dependency audit visible
- **Risk**: Known vulnerabilities in dependencies
- **Evidence**: package.json not examined, but likely contains outdated packages

#### A07:2021 - Identification and Authentication Failures
- **Gap**: No multi-factor authentication, weak password policies
- **Risk**: Account takeover through credential stuffing
- **Evidence**: Login uses only email/password without additional factors

#### A08:2021 - Software and Data Integrity Failures
- **Gap**: No integrity checks for updates or third-party services
- **Risk**: Supply chain attacks
- **Evidence**: No code signing or integrity verification mentioned

#### A09:2021 - Security Logging and Monitoring Failures
- **Gap**: Limited error logging, no audit trails
- **Risk**: Undetected breaches, inability to forensic analyze
- **Evidence**: Console.error logs but no centralized logging or monitoring

#### A10:2021 - Server-Side Request Forgery
- **Gap**: No validation of external requests in upload functions
- **Risk**: SSRF through image upload functionality
- **Evidence**: `uploadProfileImage` fetches arbitrary URIs without validation
